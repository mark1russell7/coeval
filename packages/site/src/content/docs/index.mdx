coeval is a base for declarative languages. Each language stores its programs as JSON documents. coeval gives the parts that all of these languages share. These parts are the documents, the ladder that finds an evaluator, the context of a term, and the split between pure work and effects.

The project is in the design stage. Each idea has a page with a live diagram. The diagrams use the model package of the repository, thus each answer comes from real code.

## The whole model in one loop

A store holds documents. The derive side computes the view from the store, without an effect. An event starts a run, and a run causes effects in a written order. The effects change the store, and the loop starts again.

## The ideas

- [Documents](./learn/documents/): a value in an envelope. The tab of the card is the type.
- [Kinds](./learn/kinds/): a kind is a document that names an evaluator for each verb.
- [The ladder](./learn/ladder/): a question goes to the own entry, then to the kind, then to the default.
- [Evaluation](./learn/evaluation/): results come up through ports, and parts are sealed.
- [Names](./learn/names/), [Choices](./learn/choices/) and [Effects](./learn/effects/): scope, laziness and capabilities, with the same cards.
- [Context](./learn/context/): a term reaches outside itself through five parts only.
- [Paths](./learn/paths/): each reference syntax is a list of moves.
- [Direction](./learn/direction/): back in a sequence, by moves in a structure, down and up in a tree.
- [Derive and run](./learn/derive-and-run/): order has a meaning only for effects.
- [Schedules](./learn/schedules/): when to compute is a separate layer.
