Each program is a JSON document. The key `$kind` of the document names its kind. The kind is a tag, as in a tagged union. The tag decides which evaluator gives the document its meaning.

## Why a name, and not a shape

Two documents can have the same shape and a different meaning. A record with a width and a height can be a picture, an empty box or a size limit. Only a name tells them apart.

## Data without a tag

Data from outside often has no tag. coeval gives it a tag in one of two ways:

- **The container names the kind.** A list or a collection declares the kind of its items. An item without its own `$kind` gets that kind. The own `$kind` of an item wins.
- **A classifier tags the data when it comes in.** A classifier examines the fields of a document and proposes a kind. When two shapes match equally well, it reports the ambiguity. The classifier writes a tag, and then the document has a name. The ladder does not call a classifier.

Thus each question uses a name. A guess happens only one time, at the border, and a person can see the tag that it wrote.

## A kind is a document too

A kind is a document that names an evaluator for each verb. To change how all documents of a kind evaluate, write the document of the kind. To change one document, give that document its own entry. No registry changes.
