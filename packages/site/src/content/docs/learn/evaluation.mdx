To evaluate a document, coeval asks it the verb `eval`. [The ladder](../ladder/) finds the evaluator. The evaluator gets the parts of the document, and it decides when to evaluate each part. Each result comes up to the parent through a port.

## Step through an evaluation

Select **Next** to go one event forward. Each start and each end of an evaluation is one event. The panel shows the current card: the ladder that found its evaluator, its context, the parts that its evaluator gets, and its result. Select a card to look at it.

## An evaluator gets its parts sealed

An evaluator gets each part as a sealed card. It can evaluate the part, in a context that it chooses. It can give the part to another evaluator, or keep it for later. It cannot read the part, because a sealed part has no field with its value.

<SwapDiagram client:visible />

The seal gives a simple test for a new evaluator. Evaluate the same documents with the old evaluator and the new evaluator, and compare each result. When each result agrees, the new evaluator can replace the old one.

The kernel uses the same test on itself. A reference interpreter compiles nothing, and `agree` compares each plan with it, document by document (decision D15).

## A failure is a value

An evaluation does not throw. A failure gives an error value with a code and a reason, and the port of the card shows it in red. The parent gets the error value as its result, unless it can recover.

| Code | Cause |
| --- | --- |
| `#KIND?` | The type is not a kind of the world. |
| `#NOEVAL` | No rung of the ladder gives an evaluator. |
| `#PART?` | A part has no envelope, and its position declares no type. |
| `#NAME?` | The context has no such name. |
| `#VALUE!` | A value has the wrong form for its kind. |
| `#ARGS` | Two or more parts failed. |
| `#CAP!` | The context has no capability for an effect. |
| `#CALC!` | The code of an evaluator failed. |

## Editors are different

An editor, a checker or a compiler works on the document as data. It must look inside. These tools work before an evaluation or beside it. They do not give meaning to a document, thus the seal does not apply to them.

## An evaluator is a document too

An evaluator is not one fixed formula language. A pure evaluator can be a formula. An evaluator of effects is a sequence of calls. An evaluator that builds a tree is a tree template. Each evaluator uses the language of its side, and code evaluators are the base cases.
