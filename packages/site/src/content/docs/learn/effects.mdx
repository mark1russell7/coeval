Some kinds change the world: `log` writes a line, and `write` writes a value to the store. These kinds are on the run side. Their cards have a magenta edge. Each effect becomes a numbered ticket in the world, in the order of the effects.

Only the effects have numbers. For pure parts, the order of the evaluation does not change a result. For effects, the order is the meaning.

## Capabilities

A term can cause an effect only when its context has the capability for that effect. A construct gives its parts the same capabilities or fewer. The kind `pure` gives its part no capability. Thus an effect inside `pure` fails with `#CAP!`, and the world does not change.

Select the log card, and look at the panel. Its context has no capability. The capability is a part of the context, as a name is.

A capability also permits the kinds of its namespace. The capability `store` permits the effects `store.update` and `store.remove`.

## A run

The pictures on this page are evaluations. An evaluation records each effect, and it does none. A run is the same evaluation, but the host does each effect and gives back its result. Thus a step can read the result of the step before as `last`.

A kind that holds effects has a runner. The same runner serves the evaluation and the run, thus the picture of an evaluation shows exactly what a run does. A run waits only when the host waits. Before that, it goes on at once.
