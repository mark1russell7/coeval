coeval does not read a definition to learn what a document means. It asks the document a question, and the answer comes from the first rung of the ladder that has an entry for the verb.

<GlyphKey page={3} />

1. **Own entry.** The header of a document can name an evaluator for a verb, in its field `own`. This changes one document.
2. **Kind.** The kind names an evaluator for each verb that it answers. The type comes from the envelope, or else from the container.
3. **Default.** The world has a default evaluator for some verbs, for example a JSON view.

## Try these

- Select **A card in a list**. The card is bare, and its list declares the type `card`. Its tab is dashed.
- Select **A typo**. The kind `rul` does not exist. The question stops with an error, because the ladder does not guess a name.
- Select **Plain data** and the verb `view`. No type is known, thus the default answers.
- Give the document its own entry. The question stops at the first rung.

## Why "coinductive"

A document is finite data that a store can keep and a checker can examine. Its meaning is different: it is the set of answers to questions. Nothing outside the ladder decides the meaning, and the answers come when something asks. Thus the meaning of a document is a set of observations, not a definition. The theory calls this view coinductive, and it gives coeval its name.

## The cost of the rule

A new kind is one write: a document with the entries of the kind. A new verb needs a default, or an entry in each kind that answers it. This is the usual trade between objects and data types. The default rung keeps a new verb cheap.
