The file `docs/DECISIONS.md` of the repository is the record. This page gives the summary.

## Decided

| ID | Decision |
| --- | --- |
| D1 | An evaluator is a document in the language that fits its side. It is not a program of one fixed formula language. |
| D2 | Dispatch uses names only. The type comes from the envelope or from the container. A classifier can tag data when it comes in, and the ladder does not guess. |
| D5 | A public language can live in this repository as a test language. |
| D6 | A document is a value in an envelope: `{ type, value }`, with `name` and `own` in the header. A position that declares its type holds a bare value. |
| D7 | An evaluator gets its parts sealed. A part has no field with its value. |
| D8 | The site draws each document with the view that the ladder finds. The pictures compose as the documents compose. |
| D9 | The run side is one language: a call is an envelope whose type is the path of a procedure. |
| D10 | A reference is a path from a root of the context. Each step is a question through the ladder. A type is a path into the world. Refer to [Paths](../../learn/paths/). |
| D3 | A schedule is a separate layer. coeval gives the graph of the data and the side of each kind. The engines of the hosts stay in their own projects. |
| D4 | The repository is public. Its continuous integration runs on GitHub Actions. |
| D11 | A run waits for its effects. A runner is a generator function, thus the same code serves an evaluation and a run. A capability permits its namespace. |
| D12 | Each language reads and writes coeval documents. A formula language follows shared rules for literals, operations, references, moves and constructs. |
| D13 | The languages evaluate through the kernel. A plan compiles a document one time. The static kit and the formula kit hold the shared machinery, and a language keeps only what is its own. |
| D14 | The contract of a kind tells the capabilities of its parts: the same, none, or only a list. The kernel and `check` both narrow by the contract, thus they agree. |
| D15 | A reference interpreter that compiles nothing is the oracle of one meaning. `agree` compares a plan with it, with the traced plan and with the second tier of a language. |
| D16 | The standard tree is a decorated tree. Each field of a node evaluates on demand, one time, and a cycle gives `#CYCLE!` with its chain. A failed field keeps its error. |
| D17 | Worlds and machines compose through one merge. Equal entries merge, and namespaces merge key by key. Each other clash throws one error that lists each conflict, unless the later part names its path in `replaces`. |
| D18 | A restriction removes entries of a world or a machine by path. It removes the code of a name too, because an own entry names an evaluator directly. |
| D19 | An evaluation takes a mock `perform`, so a test answers effects without promises. Each effect keeps an address that the host cannot change, and its outcome. A recorder and a replayer give record and replay. |
| D20 | `docEquals`, `sameValue` and `sameResult` share one walk. `sameResult` is for an early cutoff, thus a closure is the same only as itself, and two errors need the same reason too. |
| D21 | A host thing tells a field that holds `undefined` from a missing field with an optional `has`. A thing without `has` keeps the old reading. |
| D22 | A value type is a JSON term apart from the kinds. A language adds base types as domains of its machine, and the domains merge name by name. `unknown` fits each type, and each type fits it. |
| D23 | Each verb goes through the kernel. `prepare`, `check`, the reference and `agree` take a verb, and one ladder serves each verb. The contract serves each verb, and its effects tell what `eval` does. |
| D24 | `factsOf` gives the reads, the side, the effects and the marks `pure` and `volatile` of a document from one walk. The contracts and a hook of the machine declare the facts. A read of `event` is not volatile. |
| D25 | A type rule is part of its evaluator, thus it follows the evaluator that the ladder gives. When a host opts in, `check` gives each part its expected type and synthesizes each type. A type issue has the static code `#TYPE!`. |
| D26 | An evaluation records its reads on request. `verifyReads` resolves each free read again with the rules of `sameResult`, and an old result stays valid when each read is the same. A closure and a tree add reads of whole roots. |
| D27 | `effectsOf` gives the effects that can reach the host, from the contracts. A procedure value keeps the capabilities of its maker. `check` asks the hook `permits`, and with the option `run` it finds the waits of a run. The rule `grant` waits for the handler kind. |

## Open

No question waits on the owner. The roadmap has the work that remains.
