The file `docs/DECISIONS.md` of the repository is the record. This page gives the summary.

## Decided

| ID | Decision |
| --- | --- |
| D1 | An evaluator is a document in the language that fits its side. It is not a program of one fixed formula language. |
| D2 | Dispatch uses names only. The type comes from the envelope or from the container. A classifier can tag data when it comes in, and the ladder does not guess. |
| D5 | A public language can live in this repository as a test language. |
| D6 | A document is a value in an envelope: `{ type, value }`, with `name` and `own` in the header. A position that declares its type holds a bare value. |
| D7 | An evaluator gets its parts sealed. A part has no field with its value. |
| D8 | The site draws each document with the view that the ladder finds. The pictures compose as the documents compose. |
| D9 | The run side is one language: a call is an envelope whose type is the path of a procedure. |
| D10 | A reference is a path from a root of the context. Each step is a question through the ladder. A type is a path into the world. Refer to [Paths](../../learn/paths/). |
| D3 | A schedule is a separate layer. coeval gives the graph of the data and the side of each kind. The engines of the hosts stay in their own projects. |
| D4 | The repository is public. Its continuous integration runs on GitHub Actions. |
| D11 | A run waits for its effects. A runner is a generator function, thus the same code serves an evaluation and a run. A capability permits its namespace. |
| D12 | Each language reads and writes coeval documents. A formula language follows shared rules for literals, operations, references, moves and constructs. |
| D13 | The languages evaluate through the kernel. A plan compiles a document one time. The static kit and the formula kit hold the shared machinery, and a language keeps only what is its own. |
| D14 | The contract of a kind tells the capabilities of its parts: the same, none, or only a list. The kernel and `check` both narrow by the contract, thus they agree. |
| D15 | A reference interpreter that compiles nothing is the oracle of one meaning. `agree` compares a plan with it, with the traced plan and with the second tier of a language. |
| D16 | The standard tree is a decorated tree. Each field of a node evaluates on demand, one time, and a cycle gives `#CYCLE!` with its chain. A failed field keeps its error. |
| D17 | Worlds and machines compose through one merge. Equal entries merge, and namespaces merge key by key. Each other clash throws one error that lists each conflict, unless the later part names its path in `replaces`. |
| D18 | A restriction removes entries of a world or a machine by path. It removes the code of a name too, because an own entry names an evaluator directly. |
| D19 | An evaluation takes a mock `perform`, so a test answers effects without promises. Each effect keeps an address that the host cannot change, and its outcome. A recorder and a replayer give record and replay. |
| D20 | `docEquals`, `sameValue` and `sameResult` share one walk. `sameResult` is for an early cutoff, thus a closure is the same only as itself, and two errors need the same reason too. |
| D21 | A host thing tells a field that holds `undefined` from a missing field with an optional `has`. A thing without `has` keeps the old reading. |
| D22 | A value type is a JSON term apart from the kinds. A language adds base types as domains of its machine, and the domains merge name by name. `unknown` fits each type, and each type fits it. |
| D23 | Each verb goes through the kernel. `prepare`, `check`, the reference and `agree` take a verb, and one ladder serves each verb. The contract serves each verb, and its effects tell what `eval` does. |
| D24 | `factsOf` gives the reads, the side, the effects and the marks `pure` and `volatile` of a document from one walk. The contracts and a hook of the machine declare the facts. A read of `event` is not volatile. |
| D25 | A type rule is part of its evaluator, thus it follows the evaluator that the ladder gives. When a host opts in, `check` gives each part its expected type and synthesizes each type. A type issue has the static code `#TYPE!`. |
| D26 | An evaluation records its reads on request. `verifyReads` resolves each free read again with the rules of `sameResult`, and an old result stays valid when each read is the same. A closure and a tree add reads of whole roots. |
| D27 | `effectsOf` gives the effects that can reach the host, from the contracts. A procedure value keeps the capabilities of its maker. `check` asks the hook `permits`, and with the option `run` it finds the waits of a run. The rule `grant` waits for the handler kind. |
| D28 | The host gives the types of the roots, and a reference gets the type that its path reaches. A missing field of a closed record is a type issue. Only a type rule keeps the types of the roots for its parts. A type comes from the host, a JSON Schema or sample values. |
| D29 | A reference compiles its static path one time, in `prepare`, and each evaluation only walks the values. The kind of a type has a memo for each world. The results, the errors and the reads stay the same. |
| D30 | A host keeps one epoch for the structure and one for the data. `durable` keeps a plan and the facts for each document object, and one result for each key. A change of data compiles nothing. A pure document verifies its reads, and another document evaluates again. |
| D31 | A schedule keeps named documents as nodes under the root `world`, and it evaluates them on demand. An edge goes to a node and keeps its field, and the early cutoff is by field. Each node of a cycle gives `#CYCLE!` in each order. A node on the run side is a sink, and only the host starts a run. |
| D32 | Each context carries the grant of the kernel: the capabilities of its document. A spread keeps the grant, and each document keeps only what its grant permits. Thus compiled code cannot give a part more capabilities than its document has. |
| D33 | The analysis of a graph of nodes has its own stack: the components, the heights, the layers, the necessary nodes and the cycles. A cycle of eager edges is certain, but the demand gives the values. A demand of the host first demands its eager edges, deepest first, thus a long chain gives no `#DEPTH!`. |
| D34 | The core calculus in `SEMANTICS.md` is a part of the specification. Each inference rule names its SPEC IDs, and a test checks them. The code decides the facts that SPEC did not state: a reference in data reads the context of its reader, and one resolution follows at most 64 references. |
| D35 | A plan keeps only its data and the closures of its own code. The code of a plan and of a compiled path is on a class, and a plan makes its root and the steps of a run at their first use. A plan of one reference keeps less than 600 bytes. |
| D36 | `conforms` examines one evaluator or runner against the obligations C1 to C8. It calls the code directly with probe parts and a probe runtime. Two evaluations that differ only in what the code must not read find C4, C5 and C8. C8 is an obligation of the author of a profile. |
| D37 | Each law of the semantics has a property test on generated documents, and each law states its conditions. A test counts the cases that its conditions skip. Code that reads `doc.value` breaks EVAL.SEALED, and the test finds it. |
| D38 | A run drives a runner under an evaluator, as an evaluation does. Only a real wait gives `#CALC!`. A branch that does not run does not wait. RUN.SAME holds when no evaluator causes an effect and the host answers at once. |
| D40 | A domain can have a codec. The extension `ext.domain` holds a member of the domain as JSON, and the codec reads it again. `encodeValue` writes each host value as one document, thus each language writes the same value the same way. |
| D41 | One syntax kit reads and writes the text of each language. A profile gives the operators, the literals, the references and the calls. `parse` gives documents or issues with spans, and `print` writes the text that `parse` reads back. |
| D42 | A kind gives equations in its contract `tree`. A step to an attribute visits five rungs in order: the own part, the kind, the parent, a copy, then a default. |
| D43 | A plan can give one result object to many evaluations. A closed pure part of a plan evaluates one time at compile time, and its result is one deeply frozen value. A host must not change a result in place. |
| D44 | The tree node reads `self` through `resolve`, and not directly. A kind declares the roots that its code resolves as a whole in `reads`, and the static facts hold them. |
| D45 | `checkWorld(machine, verbs)` checks a world before a document exists. It gives one `#NOEVAL` for each kind and verb with no entry and no default. The language gives the list of verbs. |
| D46 | Equal profiles give the same evaluators and hooks of the formula kit. Thus two languages that each build the kit with one profile merge. A cache keys each kit by its profile object and by the fields that the kit reads. |
| D47 | A formula profile names its pure extensions in the new field `pureExt`. A closed part with such an extension then folds. The mark `pure` still covers only the operations. |
| D48 | The kernel gets the base type `undefined`, and `ext.undefined` gives it. The type only names the value: a document still holds it as `ext.undefined`, because JSON has no `undefined`. |
| D49 | A contract declares the effects of the other verbs in the new field `verbEffects`, and `check` with a verb tests them. A verb without an entry gives no effect issue, as before. |
| D50 | The kits of the kernel mark compiled code that cannot fail, for example a literal. A plan does not wrap that code in the code that places errors. A host cannot set the mark. |
| D51 | `#CYCLE!` keeps its code. Its reason tells a real cycle of references from a resolution that follows more than 64 references. A lookup gives `too-long` after 32 aliases without a cycle. |
| D52 | Compiled code reads the root `caps` through the grant: the capabilities that both its context and the grant permit. A widened context reads the list of its document, as in the reference. |
| D53 | The meet of two lists narrows each part, each effect and each resolution, for function code and for compiled code. A coarser list from code gives what the document permits. |
| D54 | Each grant has an epoch: the list of capabilities of the host. An effect or a resolution reads a context of another epoch as a context without a grant. |
| D55 | The reference reads the rules of a run. `agreeRun` records a run of the plan, and each other tier replays its log with the same result, effects and order of waits. |
| D56 | A closure of `fn` keeps a read of each path that its body can read, from `factsOf`. A change of a name that no closure reads keeps the old result. A closure without static reads keeps each whole root. |
| D57 | A kept read of a closure reads a node of a schedule through `known`, without a demand. A change of another node keeps the closure, and a change of the read node discards it. |
| D58 | `agreeSchedule` examines the engine of a host against an evaluation from scratch, with the generator of SCHED.ONE-MEANING. It gives the first read with a different answer. |
| D59 | `placeOf` gives the place of a node of the decorated tree from the place that the node keeps. The walker `nearest` with `eachStep` records one hop for each node on the way. Its default keeps one hop. |
| D60 | The option `fixed` of `prepare` declares names whose values stay the same. A pure part that reads only fixed names folds, and each evaluation compares the values with `Object.is`. Another value gets the code without the fold. |
| D61 | The playground reads and writes its text with `SITE_SYNTAX`, a profile of the site world. A bad text keeps the last good document and marks its span. C17 splits, and C17b waits on C11. |
| D62 | A profile names a bind symbol in `header.bind`, thus `total = 2 + 3` gives a document the header name `total`. A call form can have a name with dots, for example `math.product`. Six programs of the playground round-trip. |
| D63 | A call form names the way that its arguments make the value. `text("big")` writes a data envelope, and `panel(width: 300)` writes a record kind. A step of a path in parentheses is a document. Each program of the playground round-trips. |
| D64 | The kernel gives `WORLD_SYNTAX`, the text profile of `STD_WORLD`. A test lists each kind of the world and finds its text. The site profile is that profile, and a host spreads it to add forms. |
| D65 | A literal in a place that takes a document gets its data envelope, thus `list(1, 2)` evaluates. A profile names the places. The forms `add`, `multiply` and `greater` write an operator with one part or none, for example `add(5)`. |
| D66 | A new list of the host with the same entries in the same order is the same epoch. The root keeps only its grant, and its grant is its epoch, thus each evaluation is faster. |
| D67 | The reference records the reads of a run. `agreeRun` compares the free reads of the plan and of the reference, in their order. The plan records no read of an equation of a tree (K165). |
| D68 | An equation of a tree records its reads in the list of the evaluation that made the node. Thus `verifyReads` and a schedule see a change of the event that an equation reads. A read from `self` or from a name of the equation is not free. |
| D69 | `factsOf` gives the static reads of the equations of a tree kind, at the first document of the kind. Thus a free read of an equation has a static read, and a schedule gets a lazy edge for it. |
| D70 | The kernel keeps the code of D66. Two reference cases are 3% to 5% slower in two runs. No variant of a part gives that time back without a larger cost elsewhere. |
| D71 | The bench of a pull request repeats each comparison on two runners. A case is slower or faster only when both runs are over the bound in the same direction. |
| D72 | `pnpm typecheck` checks the bench. The test config of the core includes `bench`, and the helper `ref` of the cases gives `Json`. |
| D73 | PR #126 holds the cost of a reference into a host thing since 22d94f4. `rootContext` reads the epoch one time, and four reference cases are faster in both runs. |
| D74 | The code of a `deref` evaluator and the input of a walker get the optional `has` of D21. Without `has`, `undefined` stays a missing field. |
| D75 | A log has a JSON form for golden files: `encodeLog` writes each value through `encodeValue`, and a value without a form is a `TypeError` with its address. One replayer serves more than one run. |
| D76 | `agreeRun` uses one replayer for its tiers. The JSON form of an exception keeps its own fields and its chain of causes, also a cycle, at the version 1. |

## Open
