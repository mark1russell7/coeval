title: Research
description: Six studies compare the kernel with the theory and the known systems of their fields. Each study ends with proposals that the roadmap takes up.
---

A study compares the theory and the known systems of one field with the kernel. It ends with proposals, ranked by value for effort. A study changes no rule. The roadmap takes up each proposal as a row. The studies are in the folder [`docs/research`](https://github.com/mark1russell7/coeval/tree/main/docs/research) of the repository.

| ID | Study | The main finding | What came of it |
| --- | --- | --- | --- |
| R1 | [Staging and partial evaluation](https://github.com/mark1russell7/coeval/blob/main/docs/research/r1-staging.md) | `prepare` is a first Futamura projection, written by hand. A harness that proves one meaning comes before a faster tier. | The reference interpreter and `agree` (D15). Compiled paths are next. |
| R2 | [Algebraic effects and the run side](https://github.com/mark1russell7/coeval/blob/main/docs/research/r2-effects.md) | The run side is already a small effect system. A run records the payload of each effect, but not its outcome. | A mock `perform` for an evaluation, and the record and replay of effects (D19). |
| R3 | [Attribute grammars and the tree kit](https://github.com/mark1russell7/coeval/blob/main/docs/research/r3-attribute-grammars.md) | Demand evaluation with one memo for each node and attribute is the reference meaning. It needs no schedule. | The decorated tree (D16). Refer to [Direction](../../learn/direction/). |
| R4 | [Incremental computation and schedules](https://github.com/mark1russell7/coeval/blob/main/docs/research/r4-incremental.md) | The unit of incremental work is a document. An early cutoff needs an equality that is safe for each host value. | `sameResult` (D20). The schedule diagram gets its graph from `refsOf`. |
| R5 | [Types and abstract interpretation](https://github.com/mark1russell7/coeval/blob/main/docs/research/r5-types.md) | A type check is an abstract interpretation of the plan. The ladder finds the type rule of a kind by name. | `check` knows the names of operations. Value types and value domains are in the kernel (D22). |
| R6 | [Language workbenches and extensibility](https://github.com/mark1russell7/coeval/blob/main/docs/research/r6-workbenches.md) | coeval is the semantic half of a language workbench, as data. Before the study, a later kind won without a message. | One merge with conflict rules (D17), and the composition checklist (D18). Refer to [Composition](../../composition/). |

The section ["The order of the next work"](https://github.com/mark1russell7/coeval/blob/main/docs/ROADMAP.md#the-order-of-the-next-work) of the roadmap gives the order in which the plan takes up the proposals.
